# litertlm SWE-Agent 当前设计总结

> 文档生成时间：2026-08-31（基于 `swe_agent/` 当前代码状态）
> 范围：3 层嵌套循环架构 + 三项核心交付（OpenAI toolcall 主循环、LFM sidecar 上下文副驾、tester 自然语言验收）
> 设计原则贯穿：**约束下沉到 BUILD 层、模型只做推理**；harness bug 一律走 GLOBAL 机制一次根治。

---

## 1. 架构总览

`litertlm` 是一个本地优先的 SWE-Agent 框架，把"软件工程任务"拆成**角色分工 + 嵌套重试循环**，全部跑在本地 LM Studio（qwen2.5.1-coder-7b-instruct），零远程配额依赖。

整体数据流：

```
用户任务
  └─ analyzer(研究者/可选) ── 产出调研 findings
       └─ planner ── 产出执行契约(modules/interface/tasks) + verify_points
            └─ loop_1 (整体重试, ≤3)
                 └─ loop_2 (编码重试, ≤3)
                      └─ loop_3 (executor 原生 toolcall 循环, ≤8 步)
                           └─ lint 静态校验 (pytest 前的本地闸门)
                 └─ pytest 单杠校验 (唯一完成判定)
            └─ tester 独立只读验收 (第 4 道闸门, 自然语言验收点)
```

代码落点：
- `config.py` —— 全局配置、角色→模型映射、提示词契约、三层循环边界
- `models.py` —— Provider 接入 + 模型目录（能力归一化）+ 角色→模型路由
- `supervisor.py` —— 主循环编排（analyzer→planner→loop_1/2/3→pytest→tester）
- `roles.py` —— 各角色的系统提示词与契约解析（含 `verify_points`）
- `verify.py` —— tester 自然语言验收（第 3 样交付）
- `lfm_sidecar.py` —— LFM 副驾上下文压缩（第 2 样交付）
- `compact.py` —— 对话压缩引擎（被 sidecar 复用）
- `registry.py` —— 工具自描述注册 + 动作分发 + 全局钩子
- `harness.py` / `state.py` —— 工作区测试单杠校验 (`_run_test_bar`) + 全局状态

## 2. 三层嵌套循环（边界与语义）

| 层级 | 触发条件 | 上限（env 可改） | 语义 |
|------|----------|------------------|------|
| `loop_1` | pytest/tester 失败，或 lint 多次不过 | `MAX_ATTEMPTS=3` (`SWE_MAX_ATTEMPTS`) | 整体重试，带失败反馈重新进入编码 |
| `loop_2` | 同一 attempt 内 lint 失败 | `MAX_ROUNDS=3` (`SWE_MAX_ROUNDS`) | 重新跑 loop_3 编码 |
| `loop_3` | executor 每轮 1 个工具调用 | `MAX_STEPS=8` (`SWE_MAX_STEPS`) | 原生 toolcall 协议稳定推进 |

- **唯一完成判定（单杠校验）**：工作区内测试 `count>0 且全部通过`（`harness._run_test_bar` 返回 `"pass"`）。
- 已**彻底移除**隐藏验收测试子系统、交付物/文件落盘检查子系统、main loop 的 reviewer 门禁——"完成"语义退化为单杠校验决定。
- `loop_3` 主循环**每轮**跑单杠校验：`pass`→Agent 完成 break；`fail`→把 pytest 输出尾部回灌给模型继续修（**不动任务状态**）；`no_tests`→继续构建。
- 主循环**不每轮无脑跑**校验：纯 `read_file`/`ask`/`plan`/`todo_write` 轮要跳过，避免浪费轮次与污染上下文。

## 3. 交付一：OpenAI toolcall 主循环（原生函数调用）

**目标**：所有角色走标准 OpenAI `tool_calls` 协议，模型通过调用工具产出动作，不再手写 JSON 文本。

### 3.1 模型路由（全部本地 qwen）
- `models.py` 只保留两个标准 OpenAI 兼容 provider：`zhipu`（远程 GLM）/ `lmstudio`（本机 `http://localhost:1234/v1`）。
- `FCCapability.NATIVE_TOOLS` 归一化能力枚举——所有登记模型（glm-4.7 系、liquid/lfm2.5-1.2b、qwen2.5.1-coder-7b-instruct）均为原生 toolcall。
- `ROLE_ENV` 把角色映射到 `config` 上的模型 env：`planner/reviewer/analyzer/executor` 当前**全部指向 `qwen2.5.1-coder-7b-instruct`**（用户在 2026-08-31 决策：零远程配额）。
- 换模型只改一个 env（`PLANNER_MODEL`/`REVIEWER_MODEL`/`EXECUTOR_MODEL`），不碰角色代码。

### 3.2 主循环协议（关键修复）
之前 qwen 返回 `tool_calls: []` + 内容里塞 fenced ```json——根因是**系统提示词里残留的"手写 JSON 动作对象"契约 + 硬编码 Conway 任务的 `CONTRACT_OVERRIDE_BANNER`** 在 priming 代码生成。

修复（`config.py`）：
- 从 `SYSTEM_PROMPT` 剥离"只输出一个 JSON 动作对象""content 需转义"等旧契约文本；代码示例泛化为 `calc.py`。
- `CONTRACT_OVERRIDE_BANNER` 重写为**纯契约约束**（禁止越权改架构/接口，动作一律走工具调用），去掉任务专属文件名与"代码风格铁律"。
- `_run_loop3_executor` 用 `M.chat_toolcalls("executor", messages, tools=tools)` 走原生协议，每轮 1 个工具调用、输出后立即停止。
- **瞬时崩溃韧性**：本地模型偶发返回 `400 model has crashed` 会让 `chat_toolcalls` 抛异常。加了 `MODEL_RETRY`（`SWE_MODEL_RETRY=2`）+ try/except，覆盖"抛异常"和"返回 None"两种失败，而非只处理 None。

## 4. 交付二：LFM Sidecar（上下文管理 + 大内容压缩）

**目标**：一个无状态的小模型副驾，专职"压缩"，不承载任何主 agent 角色。

### 4.1 定位与边界
- 模型：`liquid/lfm2.5-1.2b`（本机 LM Studio，经 `SIDECAR_MODEL` 配置，默认**不与主角色一起改**——刻意保留为独立小模型）。
- 两个职责：
  1. **上下文管理**：对话自动/手动压缩（委托 `compact.py`，但强制 `model_override=SIDECAR_MODEL`，避免误用 qwen 主角色）。参考 claude-code autoCompact，超阈值把长对话压成摘要。
  2. **大内容压缩**：shell 输出 / 文件读取等工具结果落地进主上下文之前先摘要，避免噪声撑爆上下文。
- **失败一律 fail-open**：任何 LFM 调用失败都保留原文，绝不静默丢数据。

### 4.2 实现（`lfm_sidecar.py`）
- `compress_content(text, kind)`：未超阈值 / 关闭 / 失败 / 摘要不比原文短 → 返回原文（`was_compressed=False`）；否则返回 `[LFM 压缩摘要 · 原文 N 字符]\n...`。
- `auto_compact(messages)` / `manual_compact(messages, instructions)`：转发到 `compact.maybe_auto_compact` / `compact.compact_conversation` 并强制 sidecar 模型。
- 压缩阈值：`CONTENT_COMPRESS_THRESHOLD=2000`（短结果不摘要）、`CONTENT_COMPRESS_MAX_TOKENS=400`。
- `supervisor` 在 loop_3 把超长工具结果经 `lfm_compress(res)` 压缩后再 append 进 `tool` 消息；在 `_run_nested_loops` 每轮调用 `lfm_auto_compact(messages)`。

## 5. 交付三：Tester 自然语言验收（独立只读裁判）

**目标**：在确定性 pytest 之外，增加一层"用户视角"的语义验收——由独立只读 agent 逐条核实 `verify_points` 并引用证据。

### 5.1 数据流
1. **planner 产出** `verify_points`（自然语言验收点：核心功能 / 边界异常 / CLI 可运行性 / 关键算法语义），经 `_normalize_verify_points` 规范为 `[{id, point, check_hint}]`，落盘 `WORKSPACE/.swe_verify.json` + 写入 `GLOBAL_STATE["verify_points"]`（`roles.py`）。
2. **tester 消费**（`verify.py::run_tester`）：独立 loop、独立历史、只读工具集（`read_file/glob/grep/shell/finish_verify`，由 `ROLE_TOOLS['tester']` BUILD 层硬控 + loop 内二次校验动作名）。
3. **证据约束防幻觉**：`finish_verify` 必须带 `evidence`（真实 shell 输出 / 文件片段），无证据 pass 视作作弊；tester 漏提交的验收点补判 fail。这正是 Generator-Critic 的接地原则。

### 5.2 关键修复
- 修了 `verify.py` 的**潜在崩溃**：原代码读 `config.GLOBAL_STATE`（不存在，状态实际在 `state.py`）。改为 `from .state import GLOBAL_STATE`。该 bug 会让 tester 首次触发即 `AttributeError`。
- 同样给 tester 的 `M.chat_toolcalls("tester", ...)` 包了 `MODEL_RETRY` + try/except。
- `verify_gate()` 是对外入口：`FORGE_TESTER_MODEL` 为空=复用 executor（qwen-7b），`off`=关闭。

## 6. 完成标准与校验闸门（全链路）

| 闸门 | 类型 | 位置 | 说明 |
|------|------|------|------|
| lint | 静态校验 | loop_2 之后、pytest 之前 | pyflakes / 语言服务器抓重复定义·类型·未定义名 |
| pytest 单杠 | 确定性 | `_run_test_bar` | **唯一完成判定**：count>0 且全绿 |
| tester | 语义验收 | done 时第 4 道 | 独立只读 agent 核对 `verify_points`（可关闭） |

- 校验失败**绝不 mass-reset 任务状态**：只回灌错误详情给模型，任务一旦 done 保持 done。
- 跨任务记忆 `agent_memory.json` 注入 system prompt 时**只保留 `lesson` 正文**，不渲染 `ts`/`verdict`，避免与运行时日志混淆；"无洞察力的通用失败结论"既不落盘也不注入。

## 7. 关键配置旋钮（config.py）

| 配置 | 默认 | 作用 |
|------|------|------|
| `PLANNER/REVIEWER/ANALYZER/EXECUTOR_MODEL` | `qwen2.5.1-coder-7b-instruct` | 角色→模型，全本地 |
| `SIDECAR_MODEL` | `liquid/lfm2.5-1.2b` | LFM 副驾模型（独立于主角色） |
| `SWE_MODEL_RETRY` (`MODEL_RETRY`) | `2` | 单次推理瞬时崩溃重试 |
| `SWE_MAX_ATTEMPTS/ROUNDS/STEPS` | `3/3/8` | 三层循环边界 |
| `SWE_LINT_ENABLED` | `1` | lint 闸门开关 |
| `EXECUTOR_ALLOW_AGENT` | `0` | Executor 禁止派发子智能体（亲自实现+自测） |
| `ALLOW_REPLAN` | `0` | 关闭"重规划"逃逸口，强制 Executor 自 debug |
| `CONTENT_COMPRESS_THRESHOLD` | `2000` | 工具结果压缩阈值 |
| `AUTO_COMPACT_ENABLED` | `1` | 对话自动压缩 |
| `FORGE_TESTER_MODEL` | `""` | 独立验收模型（`off`=关闭，空=复用 executor） |

## 8. 已知边界与残留

1. **qwen-7b 能力边界**：7B 写 Go / 复杂多文件工程偏弱，常产半截文件或退回 pytest；在确定性任务上能跑通原生 toolcall（已实证 3 工具干净调用），但**难以有机到达 tester `pass`**——这是模型能力问题，非 harness bug。需要更强裁判时可设 `FORGE_TESTER_MODEL` 指向更强模型。
2. **单杠校验已落地的两个坑**（勿回退）：(a) 主循环不可每轮无脑跑校验；(b) `_build_validation` 测试文件列表必须过滤磁盘不存在的幽灵路径。
3. **休眠代码**：`layers.py` 仍保留旧的 flat 函数（`run_l1_propose`/`run_l2_fence`/`run_l3_sense`），当前架构已不再调用，属可清理项（用户未要求）。

### 一句话结论
当前设计把"约束写进 BUILD 层、模型只做推理"贯彻到底：原生 OpenAI toolcall 主循环（全本地 qwen）+ LFM 无状态副驾负责上下文压缩 + 独立只读 tester 做自然语言验收，单杠 pytest 作为唯一完成判定，三者均经实证跑通、并修掉了 narration / 潜在崩溃 / 幽灵路径等 root-cause 类 bug。
